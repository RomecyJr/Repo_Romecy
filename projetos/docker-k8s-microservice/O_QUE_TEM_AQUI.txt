🎯 OBJETIVO DESTA PASTA:
   Criar uma aplicação web que funciona em qualquer lugar

📝 EXPLICAÇÃO SIMPLES:
   Você já teve problema de "funciona no meu computador mas não no
   servidor"? Docker resolve isso! Ele empacota tudo (código + ambiente)
   em uma caixinha que roda igual em qualquer lugar.

🔧 O QUE FAZ:
   ✓ API simples em Python que responde "Hello World"
   ✓ Empacota a aplicação em container (caixinha isolada)
   ✓ Permite rodar várias cópias ao mesmo tempo
   ✓ Orquestra múltiplos containers com Kubernetes

💻 TECNOLOGIA USADA:
   → Docker (empacota aplicações)
   → Kubernetes (gerencia containers)
   → Python/Flask (linguagem de programação)

📂 ESTRUTURA DE ARQUIVOS:

   📁 src/
      └─ app.py ........................ Código da aplicação

   📁 k8s/
      ├─ deployment.yaml ............... Como rodar no Kubernetes
      └─ service.yaml .................. Como acessar de fora

   📄 Dockerfile ....................... Receita para criar container
   📄 docker-compose.yml ............... Roda localmente fácil
   📄 requirements.txt ................. Lista de dependências Python
   📄 README.md ........................ Manual completo

═══════════════════════════════════════════════════════════════════════

🎓 PARA INICIANTES:

   Docker = Tupperware para software
   Cada container é uma marmita isolada com tudo que o app precisa.

   Kubernetes = Robô que cuida das marmitas
   Se uma falha, ele cria outra. Se tem muita gente, ele cria mais.

═══════════════════════════════════════════════════════════════════════

📖 ANALOGIA DO DIA A DIA:

   Imagine que você tem um restaurante (servidor):

   SEM DOCKER:
   - Cada prato precisa da cozinha toda
   - Se um chef erra, afeta outros pratos
   - Mudar menu é complicado

   COM DOCKER:
   - Cada prato vem em marmita pronta
   - Um prato não interfere no outro
   - Trocar pratos é só trocar marmitas

═══════════════════════════════════════════════════════════════════════

🚀 CASO DE USO REAL:

   Netflix, Spotify, Uber... todos usam containers!

   Por quê? Imagine atualizar o sistema sem derrubar o serviço:
   1. Cria novos containers com nova versão
   2. Direciona usuários aos poucos
   3. Se der problema, volta pros antigos
   4. Tudo sem parar o serviço!

═══════════════════════════════════════════════════════════════════════

🎯 FLUXO DE TRABALHO:

   1. Desenvolvedor escreve código → app.py
   2. Docker empacota em container → Dockerfile
   3. Sobe local para testar → docker-compose up
   4. Publica no Kubernetes → kubectl apply
   5. Kubernetes gerencia tudo automaticamente!
